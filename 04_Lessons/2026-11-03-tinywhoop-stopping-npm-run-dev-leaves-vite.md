# Остановка фоновой `npm run dev` под Windows оставляет vite жить на порту

**Что было.** Агент поднял `npm run dev` фоновой задачей для полёта владельца, после полёта остановил задачу — и
следующий `npm run shot` написал «reusing dev server on :5173». Порт держал `node …\vite\bin\vite.js` той же папки:
остановка убила `npm`, а не его дочерний процесс. Проверка корня (`/__root`, урок
[2026-11-02](2026-11-02-tinywhoop-worktree-shares-package-name.md)) сработала — сервер был свой, — но живой сервер с
HMR рядом с прогоном мутаций — ровно то, что приборы запрещают (мутант подгружается в открытую страницу, а восстановленный
файл сервер может не перечитать).

**Почему важно другим.** Невидимый сервер переживает задачу, и следующий прибор меряет не то, что агент думает: при двух
worktree — может быть и чужой папки, если проверка сервера слабее корня.

**Как применить.** После остановки dev-сервера проверить порт (`Get-NetTCPConnection -LocalPort 5173 -State Listen` и
`CommandLine` процесса) и остановить `vite.js` по PID. Прогоны мутаций и записи калибровки начинать с этой проверки.

## Подтверждения

- 2026-11-03, TinyWhoopPlayground, D-57 при закрытии этапа: та же картина после приёмочного полёта владельца — задача `npm run dev` остановлена, порт 5174 держал `vite.js` той же папки (PID 27128); второй раз за этап, после него — проверка порта и остановка по PID.
