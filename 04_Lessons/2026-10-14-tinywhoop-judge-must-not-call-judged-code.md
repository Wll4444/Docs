# Ожидаемое значение, посчитанное функцией, которую проверяют, соглашается с её ошибкой

**Что было.** Сценарий `hover` судил высоту тона моторов. Он сравнивал пик спектра реального звукового выхода с
частотой, «выведенной из ω_hover». Вывод делала `toneHz` — та же функция, которой строится голос. Мутация «тон — частота
вала, без лопастей» (в 3 раза ниже) прошла прогон зелёной: голос и эталон опустились вместе. Юнит той же функции её
поймал, потому что считал ожидаемое значение прямо из чисел `config/`. После того как судья стал выводить частоту сам
(`ω_hover · rpm / 60 · лопасти` из `config/`), мутация краснеет и в браузере.

**Почему важно другим.** Приём «ожидаемое = выведенное из конфигурации» хорош, пока вывод не идёт через проверяемый
код. Позвать готовую функцию удобно, и это незаметно превращает проверку в «код согласен сам с собой». Такая проверка
зелёная при любой ошибке в этой функции, хотя по виду она сравнивает измерение с теорией.

**Как применить.** В судье или юните ожидаемое значение собирается из исходных чисел и формулы, записанной заново. Не
импортировать функцию, которую проверка охраняет. Проверка проверяется мутацией именно этой функции: если мутация
выжила, судья, скорее всего, её зовёт.
