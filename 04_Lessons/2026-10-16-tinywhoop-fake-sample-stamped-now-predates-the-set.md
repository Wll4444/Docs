# Подменный сэмпл с отметкой «ровно сейчас» может быть сделан до установки — ждать отметку строго позже

**Что было.** Подменный пульт харнесса TinyWhoop ставит отчёту отметку его 4-мс границы
(`floor(t / 4) · 4`) и делает отчёт при первом чтении; сценарий ставит стик и опрашивает, пока не
придёт сэмпл с отметкой `>= since`. `performance.now()` в Chrome огрублён (100 мкс), и два
`setThrottle` через пару шагов физики попадали в один тик: отчёт с отметкой ровно `since` уже был
сделан чтением ПЕРВОЙ установки и нёс старый стик. Новый сценарий этапа L01 прочитал газ 0.9 как 0 —
3 прогона из 9 на лаборатории (со строгим `>` — 0 из 9); проверка защёлки газа вышла бы «пустой», а показалась бы
дефектом игры. Старые сценарии не задевали гонку: между их установками проходили сотни шагов.

**Почему важно другим.** «Дождаться сэмпла не раньше момента установки» — естественная форма
синхронизации подменного ввода с опросом (геймпад, указатель, сеть с отметками). На огрублённых часах
`>=` пропускает сэмпл, сделанный до установки, и ошибка редкая и зависит от темпа сценария — её легко
списать на игру.

**Как применить.** Ждать отметку **строго позже** момента установки (`>`), если отметка — граница
периода отчёта, а отчёт делается лениво; либо делать отчёт заново при каждой установке. Проверять
чтение по прочитанному значению, а не по «отчёт пришёл»: сценарий L01 теперь падает, если газ
прочитан не тем, что поставлен.
