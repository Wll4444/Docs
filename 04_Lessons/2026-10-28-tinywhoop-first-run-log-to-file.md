# Первый прогон набора — в файл целиком: падение, которое не повторилось, без имён не засчитать

**Что было.** В TinyWhoop открыт долг: первый тест файла изредка падает по таймауту на холодном импорте, два проявления, третье
по правилу реестра делает его целью следующего этапа. Первый полный прогон в начале L08 дал 842 из 844, но вывод был обрезан
`| tail -8` — в него попала только сводка. Три повтора, один с очищенным кэшем, прошли целиком. Было ли это тем самым долгом,
доказать нечем: проявление записано как неподтверждённое, счётчик не сдвинулся. Решение, ради которого счётчик существует,
повисло на обрезанном выводе.

**Почему важно другим.** Редкое падение чаще всего случается на первом прогоне за сессию (холодные кэши) — и именно этот прогон
агент обычно смотрит через `tail`, потому что ждёт зелёного. Повтор его не восстановит. Счёт проявлений требует доказательства,
а доказательство — это имена упавших тестов и их ошибки.

**Как применить.**
- Первый прогон набора в сессии — в файл целиком (`npm test > лог 2>&1`), из файла читать сводку и строки `FAIL`.
- Падение, которое не повторилось, записывать в долг с именами и временем, даже если «повтор зелёный».
- Без имён — помечать «не подтверждено» и не двигать счётчик: правило должно стоять на числах, а не на догадке.
