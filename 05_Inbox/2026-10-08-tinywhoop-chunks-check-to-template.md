# Перенести в Template проверку «ленивого чанка» по собранному `dist/` — `scripts/chunks.mjs`

**Почему.** Любой проект, чьи dev-инструменты лежат в ленивых чанках (панель leva в TinyWhoop и Nature, оверлей `?perf=1`
в Template), держит обещание «обычная сессия этого не скачивает» только исходником: `lazy(() => import(...))`. Один статический
импорт где угодно втягивает пакет во вход, и ни один тест исходника этого не видит. В TinyWhoopPlayground проверка читает собранный
`dist/` — статическое замыкание входа не содержит подписи пакета, чанк панели есть, содержит её и достижим только динамическим
`import()` — и проверена ломкой (мутация P2: статический импорт → красная). Урок по подписи и положительному контролю —
[2026-10-08-tinywhoop-panel-and-harness-share-one-door](../04_Lessons/2026-10-08-tinywhoop-panel-and-harness-share-one-door.md).
Скрипт — `TinyWhoopPlayground/scripts/chunks.mjs` (≈ 80 строк, без зависимостей), запуск `npm run build && npm run chunks`.

**Что именно сделать.** Положить `scripts/chunks.mjs` в `Template/scripts/` с параметрами «имя чанка» и «подпись пакета»
(сейчас — `TuningPanel-*.js` и `\bleva__|levaType`, зашиты константами сверху файла); в Template подпись и имя — под `PerfOverlay`
или под то, что там ленивое. Добавить в `package.json` строку `"chunks": "node scripts/chunks.mjs"` и пункт в
`Docs/06_Reference/` Template. Подпись — не слово пакета (`leva` есть в «elevation»), а строка, которую пишет только он.

**Чем рискуем, если не сделать.** Каждый проект проверяет «панели нет в основном чанке» глазом по отчёту сборки, и первый
случайный статический импорт тянет UI-пакет всем игрокам, пока кто-нибудь не посмотрит на размер.
