# TinyWhoop Flight Playground — план прототипа

## 1. Идея

Небольшой веб-проект на **React Three Fiber / Three.js + Rapier**, представляющий собой симуляцию полёта маленького FPV-дрона класса **TinyWhoop / Air65** в замкнутых пространствах.

Основная идея:

> Взять настоящий Radiomaster Pocket и полетать виртуальным TinyWhoop по небольшим помещениям, гаражам, подземным парковкам, заброшенным домам и другим замкнутым пространствам.

Проект не обязательно сразу делать полноценной игрой. Первая цель — создать **Flight Playground**, в котором просто приятно летать.

---

## 2. Почему проект интересен

- Тема связана с реальным хобби и опытом полётов на микродронах.
- Есть настоящий физический контроллер — **Radiomaster Pocket**.
- Проект хорошо подходит для изучения физики в web game development.
- Можно начать с очень простого прототипа и постепенно наращивать реализм.
- Не требуется большой open world: небольшие детализированные пространства хорошо подходят для веб-игры.
- Качество проекта можно оценивать субъективно и практически:  
  **«Подключил пульт, взлетел — и хочется летать дальше?»**

---

## 3. Технологии

Предполагаемый стек:

- React
- React Three Fiber
- Three.js
- Rapier
- Web Gamepad API / другой способ получения RC input
- GLTF/GLB для моделей окружения
- собственная flight model поверх физики Rapier

---

## 4. Главная техническая проблема

Главная сложность — не сами столкновения, а **ощущение управления TinyWhoop**.

Не обязательно сразу делать полноценную аэродинамическую модель уровня FPV-самосимуляторов.

Главный принцип:

> Сначала добиться убедительного поведения дрона, а затем постепенно усложнять физическую модель.

---

## 5. Предлагаемая архитектура

```text
Radiomaster Pocket
        │
        ▼
    RC Input
        │
        ├── Throttle
        ├── Roll
        ├── Pitch
        └── Yaw
        │
        ▼
  Flight Controller
        │
        ├── attitude
        ├── angular velocity
        └── stabilization
        │
        ▼
     Motor Model
        │
        ▼
   Forces / Torque
        │
        ▼
      Rapier
        │
        ▼
      Drone
        │
        ▼
   FPV Camera
```

### Разделение ответственности

**Rapier:**
- rigid body;
- столкновения;
- гравитация;
- физическая интеграция;
- импульсы и контакты.

**Flight Controller / собственный код:**
- обработка стиков;
- стабилизация;
- расчёт тяги;
- roll/pitch/yaw;
- модель четырёх моторов;
- дополнительные эффекты поведения дрона.

# 6. Этапы разработки

## V0.1 — Flight Playground

Одна простая коробка-комната.

Без красивой графики.

Сделать:

- drone rigid body;
- камера от первого лица;
- throttle;
- roll;
- pitch;
- yaw;
- гравитацию;
- базовую стабилизацию;
- возможность взлететь и приземлиться.

### Цель

Получить первый ответ на вопрос:

> «Приятно ли управлять этим дроном с Radiomaster Pocket?»

---

## V0.2 — Базовая физика

Добавить:

- пол;
- стены;
- потолок;
- столкновения;
- импульс при ударе;
- небольшое сопротивление;
- ограничение/настройку максимальной скорости;
- настройку массы и тяги.

На этом этапе можно экспериментировать с параметрами вместо попытки сразу получить физически правильную модель.

---

## V0.3 — Более реалистичный TinyWhoop

Перейти от упрощённой модели к четырём виртуальным моторам:

```text
       M1       M2
        \       /
         \     /
          DRONE
         /     \
        /       \
       M3       M4
```

Исследовать:

- индивидуальную тягу моторов;
- roll torque;
- pitch torque;
- yaw torque;
- реакцию на изменение throttle;
- инерцию;
- потерю высоты при наклоне;
- поведение при резких манёврах.

Не обязательно сразу моделировать настоящую аэродинамику.

---

## V0.4 — FPV-камера

Настроить камеру так, чтобы управление ощущалось как FPV:

- широкий FOV;
- положение камеры внутри корпуса;
- наклон камеры;
- camera smoothing / отсутствие smoothing — сравнить варианты;
- естественное вращение вместе с дроном;
- при желании — небольшой camera shake при ударах.

Отдельно исследовать, насколько сильно камера должна отличаться от обычной игровой third-person камеры.

---

# 7. Первое настоящее окружение

После того как полёт станет интересным, сделать небольшую комнату.

Пример:

```text
┌──────────────────────────┐
│                          │
│        ┌──────┐          │
│        │      │          │
│        │      │          │
│                          │
│              ┌──────┐    │
│              │      │    │
│                          │
│   START ●                │
└──────────────────────────┘
```

Можно добавить:

- двери;
- столы;
- коробки;
- мебель;
- небольшие препятствия;
- ворота;
- узкие проходы.

Главная задача — проверить, насколько интересно **маневрировать в ограниченном пространстве**.

---

# 8. Возможное развитие окружений

Не делать большой мир.

Лучше серия небольших самостоятельных локаций:

1. Комната / квартира
2. Гараж
3. Подземная парковка
4. Склад
5. Заброшенный дом
6. Недостроенное здание
7. Чердак
8. Технические помещения

Особенность TinyWhoop можно использовать как часть дизайна:

> Маленький дрон позволяет исследовать места, куда обычный человек или большой FPV-дрон попасть не может.

---

# 9. Возможные игровые механики

Добавлять только после того, как сам полёт уже работает.

### Свободный полёт
Просто исследовать локацию.

### Checkpoints
Пролететь через последовательность ворот.

### Time Trial
Пройти маршрут за минимальное время.

### Precision Flight
Пролетать через небольшие отверстия и узкие места.

### Exploration
Найти определённые точки или объекты.

### Landing
Точно посадить дрон в указанное место.

### Ghost / Replay
Записывать полёт и сравнивать с предыдущей попыткой.

---

# 10. Параметризация

Важно с самого начала вынести основные параметры в конфигурацию.

Например:

```text
Drone
- mass
- max thrust
- motor response
- drag
- angular drag
- max angular velocity
- camera FOV
- camera angle

Room
- width
- height
- length

Flight
- gravity
- stabilization strength
- throttle response
- pitch/roll response
- yaw response
```

Это позволит быстро экспериментировать с ощущением полёта без переписывания физики.

---

# 11. Что НЕ делать на первом этапе

Не пытаться сразу реализовать:

- полноценную аэродинамику;
- точную модель пропеллеров;
- PID Betaflight один-в-один;
- battery sag;
- prop wash;
- ground effect;
- wind simulation;
- сложную графику;
- большой open world;
- сетевую игру;
- полноценную карьеру.

Всё это потенциальные направления, но не цель первого прототипа.

---

# 12. Главный принцип разработки

Разрабатывать **от ощущения управления**, а не от графики.

Приоритет:

```text
RC input
   ↓
Flight model
   ↓
FPV camera
   ↓
Rapier collisions
   ↓
Simple room
   ↓
Interesting environments
   ↓
Gameplay
   ↓
Visual polish
```

Если полёт неинтересный — красивая локация проект не спасёт.

Если полёт приятный — даже серая коробка уже может быть хорошим прототипом.

---

# 13. Критерий успеха первого прототипа

Минимальная версия считается успешной, если:

1. Radiomaster Pocket подключается к браузеру.
2. Стики корректно читаются.
3. Дрон может взлететь.
4. Roll / Pitch / Yaw ощущаются естественно.
5. Дрон имеет инерцию.
6. Дрон сталкивается со стенами и полом через Rapier.
7. FPV-камера создаёт ощущение полёта.
8. После пяти минут полёта возникает желание продолжить.

Последний пункт — самый важный.

## Итог

Это экспериментальный проект, сочетающий:

**реальное FPV-хобби + web game development + физику + Three.js/R3F + Rapier + настоящий RC-контроллер.**

Главная цель первой версии — не сделать полноценный симулятор, а ответить на простой вопрос:

> **Можно ли сделать в браузере маленький TinyWhoop, которым действительно приятно управлять с настоящего пульта?**

Если ответ окажется положительным, проект можно постепенно развивать в полноценную игру про исследование замкнутых пространств на FPV-дроне.
