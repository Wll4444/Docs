## 💭 Dream-tier идея (на будущее, требует пререквизитов)

### Мини машинки в пустыне (Уровень: Capstone / несколько тяжёлых систем сразу)
*Vehicle physics + процедурный террейн + модульная кастомизация + строительные паззлы.*

- **Суть:** Одиночная survival-exploration игра. Старт в городе на обычном "жуке" с вещами
  на багажнике, путешествие по сети дорог и бездорожью пустыни (песок, овраги, горы).
  Цель — добраться до достопримечательностей и сфотографировать их. По пути машина
  постепенно модернизируется в автостопах: большие колёса, нестандартный двигатель,
  торчащий из капота, и т.д.
- **Препятствия:**
    - Рельеф (овраги, горы) — требует апгрейдов проходимости.
    - Реки — нужно строить мост.
    - Болота — либо большие колёса, либо дорога из брёвен.
    - "Монстры" — не боевая механика, а часть динамических препятствий на пути (объезд/обход,
      без активного противодействия).
- **Визуал:** Low-poly 3D, вид сверху, камера плавно вращается по кругу вокруг машины.
- **Ключевые навыки/системы:**
    - Vehicle physics (raycast vehicle controller в Rapier) — настройка подвески и сцепления
      на пересечённой местности.
    - Процедурный/heightmap-террейн + trimesh-коллайдеры, LOD для больших карт.
    - Модульная кастомизация машины (hot-swap мешей или точки крепления под апгрейды) —
      хорошо ложится на существующий Blender-пайплайн для генерации ассетов.
    - Мини-система строительства (мост, брёвна) — размещение объектов + физическая
      проверка "выдерживает вес".
    - Лёгкий AI/логика для динамических препятствий-"монстров" (без боя, только избегание).
- **Пререквизиты по навыкам:** физика + террейн лучше сначала отработать на **Marble Run**
  (п. 3), а управление транспортом — на **Drone simulator** (из основной последовательности),
  прежде чем браться за этот проект.
- **Платформа:** веб, десктоп-приоритет (мобильный веб может проседать по FPS на больших
  картах с террейном и физикой; как облегчённая версия — возможна позже).
- **Статус:** идея зафиксирована, требует дальнейшего обдумывания и, возможно, отдельного ТЗ
  по аналогии с `rubiks_cube_plan.md`.
